## NeoHosting cPanel (shared hosting)

- cPanel: https://web14-cpn.neohosting.id:2083/ , account `wwwarmst`.
- **Site IP is the Shared IP `<SHARED_IP>`** (cPanel sidebar > General Information). `<CPANEL_HOST_IP>` is only the cPanel hostname's IP and serves someone else's default site. Do not use it.
- PHP 8.2 (needs 8.1+). Set `memory_limit` >= 256M. Extensions: mysqli, curl, mbstring, gd/imagick, zip, intl, xml.
- Host runs an anti-bot layer: unauthenticated requests get a "One moment, please..." loader page, so `curl` cannot read the site. Check pages in a browser. Ask NeoHosting to whitelist `/wp-json/doku/` (DOKU webhooks are automated requests).
- Softaculous "SoftWP" installs WordPress with bundled extras. Decline "AI Assistant" and onboarding. Remove SpeedyCache (breaks cart/checkout), Pagelayer, FormLayer, Social Login. Keep Backuply, GoSMTP (order email); CookieAdmin and SiteSEO optional.
- **Deleting a Softaculous install removes files and database.** Never delete a domain or install without checking what it holds.

## DNS (Cloudflare)

- Zone `armstronger.web.id` is on Cloudflare (kenia / zod nameservers). The apex has no records.
- `shop` A record -> `<SHARED_IP>`, **DNS only (grey cloud)** so cPanel AutoSSL can validate. HTTPS is issued and valid.
- If proxied later: SSL/TLS mode Full (strict); bypass cache for `/cart/`, `/checkout/`, `/my-account/`, `/wp-json/`.

- Decision 2026-09-27: keep `/wp/` for the deployment check. For a customer demo, reinstall at the subdomain root (Softaculous: remove the install incl. files + DB, install again with a blank directory).

## Install steps on the host (wp-admin)

1. Plugins: remove unneeded bundled ones.
2. Install and activate WooCommerce (skip the wizard).
3. Appearance > Themes > Upload `woocommerce/deploy/acme-theme.zip` (rebuild from `woocommerce/theme/acme/` with forward-slash zip paths, e.g. Python `zipfile`; PowerShell `Compress-Archive` writes backslashes). Activate.
4. Install and activate DOKU Payment. WooCommerce > Settings > Advanced > Features: turn **High-Performance order storage off** (plugin incompatible).
5. WooCommerce > Settings > General: Indonesia / DKI Jakarta, IDR, 0 decimals, thousand separator `.`. Payments: enable COD and bank transfer. Site visibility: Live (or Coming soon to hide).
6. Settings > Permalinks: Post name.
7. Products > Import `woocommerce/deploy/products.csv` (generated by `node woocommerce/seed/csv.js` from `mockup-v2/app.js`; images are fetched from DummyJSON URLs).
8. Appearance > Menus: Beranda, Semua produk, Tentang. Create pages `about` and `faq` (the theme has `page-about.php` / `page-faq.php`).

## DOKU (payments)

- Official plugin `doku-payment`. Credentials live in the DB option `woocommerce_doku_gateway_settings` (`sandbox_client_id`, `sandbox_shared_key`, `environment_payment_jokul=false`). Enter them in WooCommerce > Settings > Payments > DOKU. Never commit them. The Secret Key was pasted in chat once during development, so rotate it before real use.
- Notification URL in the DOKU dashboard: `https://shop.armstronger.web.id/wp/wp-json/doku/notification` (QRIS: `/wp/wp-json/doku/qrisnotification`). Without it orders stay pending after payment.
- QRIS needs its own QRIS Client-ID, Shared Key and MPAN (WooCommerce > Settings > Payments > DOKU Checkout). Not obtained yet.
- Hosted DOKU Checkout page works in sandbox (tested locally on 2026-09-27).

## Access control

- Hide from the public: WooCommerce > Settings > Site visibility > Coming soon (admins still see the site), or cPanel > Directory Privacy (this also blocks DOKU webhooks, so turn it off when testing payments). Also Settings > Reading > discourage search engines.

## Local dev gotchas (for reference)

- The local container's WordPress HTTP client gets HTTP 434 from wordpress.org, so plugin installs use zips fetched with curl. Run wp-cli inside `woocommerce_wp_1` as uid 33.
- `wp-app` / `wp-db` podman containers belong to another project. Do not start them.
